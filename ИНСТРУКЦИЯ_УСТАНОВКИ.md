# MedFlow — как всё запустить и что показать

Простыми словами. Ничего набирать вручную не нужно — почти всё делается двойным кликом.

---

## Главное: 5 файлов, по которым нужно кликать

| Файл | Когда кликать | Что произойдёт |
|---|---|---|
| `setup.cmd` | **один раз** на новом компьютере | Сам поставит Java, Git, MySQL; создаст папку `C:\MedFlow` и команду `docker` |
| `start.cmd` | **каждый раз** перед работой | Поднимет базу и запустит программу |
| `stop.cmd` | когда закончил | Остановит программу и базу |
| `verify-all.cmd` | когда нужно показать тесты и проверки | Прогонит **все** проверки и выведет короткий итог |
| `show-db.cmd` | когда нужно показать базу данных | Покажет таблицы, строки, миграции и индексы |

**Окно `start.cmd` больше не закрывается само.** Оно остаётся открытым, пока работает программа. Если программа не запустилась — окно всё равно останется и покажет текст ошибки (в конце нужно нажать любую клавишу).

Дополнительно: `open-mysql.cmd` откроет живой консоль MySQL, а `open-db-gui.cmd` — HeidiSQL (если он установлен).

---

## 1. Первый раз (новый компьютер)

1. Скопируй всю папку проекта на новый компьютер.
2. **Двойной клик по `setup.cmd`**. Дождись слова `setup is complete`.
3. Закрой окно и **открой новое** — это важно, иначе система не увидит новые настройки.
4. Всё. Больше ничего ставить не надо. Интернет нужен был только на этом шаге.

> Повторный запуск `setup.cmd` безопасен: уже установленное он не скачивает заново.

---

## 2. Каждый раз, когда хочешь поработать

1. **Двойной клик по `start.cmd`**.
2. Откроется окно. В нём будет:
   - `[1/2] Поднимаю базу данных...`
   - `[2/2] Запускаю программу...`
   - `Tomcat started on port 8080`
3. Браузер откроется сам. Если нет — открой <http://localhost:8080>.
4. Окно **не закрывай**, пока работаешь — это и есть работающая программа.
5. Когда закончил: `Ctrl+C` в окне, затем **двойной клик `stop.cmd`**.

### Если `start.cmd` показал «MedFlow уже запущена»

Это нормально: программа уже работает (например, окно с ней свёрнуто). Скрипт просто открыл браузер.
Чтобы перезапустить: закрой окно со старой программой или запусти `stop.cmd`, затем снова `start.cmd`.

> Раньше окно закрывалось, потому что второй экземпляр пытался занять уже занятый порт 8080 и падал, а окно не ждало нажатия клавиши. Теперь скрипт это проверяет заранее и окно всегда остаётся открытым.

## 3. Как показать ВСЕ тесты и проверки

Пока приложение работает (окно из шага 2 не закрыто):

**Двойной клик по `verify-all.cmd`**.

Сначала пойдут подробные строки `[PASS] ...`, а в самом конце — короткая таблица:

```text
============================================================
  MedFlow - ИТОГ ПРОВЕРОК
============================================================
  1/3  Тесты Java (JUnit / MockMvc)                 33/33  [OK]
  2/3  Проверка программы (API, роли, CSRF, запись)  31/31  [OK]
  3/3  Проверка базы MySQL                          22/22  [OK]
------------------------------------------------------------
  ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ
============================================================
```

**Вот эту таблицу и нужно показывать** — она одна заменяет все три отчёта.
Если вместо `[OK]` видишь `[FAIL]` — значит приложение не запущено, сначала сделай шаг 2.

Проверено на этой машине: **33 + 31 + 22 = 86 проверок, все зелёные**.

## 4. Как показать саму базу данных

### Вариант А — готовый обзор (самый простой)

**Двойной клик по `show-db.cmd`.** Появится:

1. версия MySQL;
2. список из 9 таблиц;
3. сколько строк в каждой таблице;
4. записи по статусам (`SCHEDULED`, `COMPLETED`, `CANCELLED`);
5. последние 8 записей на приём;
6. применённые миграции Flyway V1, V2, V3;
7. уникальный индекс, который не даёт записать двух людей на один слот.

### Вариант Б — живая консоль

**Двойной клик по `open-mysql.cmd`**, затем введи:

```sql
SHOW TABLES;
SELECT status, COUNT(*) FROM appointments GROUP BY status;
SELECT id, doctor_id, start_time, end_time, status, price FROM appointments ORDER BY id DESC LIMIT 10;
exit;
```

### Вариант В — красивый окно (HeidiSQL)

**Двойной клик по `open-db-gui.cmd`.** Если HeidiSQL не установлен — скрипт напишет, откуда его скачать, и выдаст готовые параметры подключения:

```text
Хост:     127.0.0.1
Порт:     3306
Пользователь: hospital
Пароль:   hospital_pass
База:     hospital_db
```

Скачать: <https://www.heidisql.com/download.php> (бери portable-версию, распакуй и запусти `heidisql.exe`).

### ⚠️ Одна важная деталь (из-за неё был непонятный терминал)

**Не пиши в PowerShell `-h127.0.0.1`** — PowerShell «откусывает» часть и получается `-h127`, из-за чего выходит ошибка:

```text
ERROR 2005 (HY000): Unknown MySQL server host '127'
```

Правильно писать так:

```powershell
& "$env:USERPROFILE\mysql84\bin\mysql.exe" --protocol=tcp --host=127.0.0.1 --port=3306 --user=root --database=hospital_db -e "SHOW TABLES;"
```

Или просто пользуйся готовыми `show-db.cmd` / `open-mysql.cmd` — там уже всё написано правильно.

## 5. Как показать саму программу

Открой <http://localhost:8080> и войди под разными ролями:

| Роль | Логин | Пароль | Что показать |
|---|---|---|---|
| Регистратор | `reception` | `Reception123!` | Календарь, картотека, запись на приём |
| Администратор | `admin` | `Admin123!` | Врачи, услуги, расписание, отчёты |
| Врач | `doctor.ivanov` | `Doctor123!` | Только свои приёмы; чужие разделы дают `403` |
| Пациент | `patient.demo` | `Patient123!` | Мои визиты, мои направления |

Что стоит сделать на глазах:

1. Зайти как `reception`, выбрать врача и дату — посмотреть свободные слоты.
2. Записать пациента → появится запись со статусом `SCHEDULED` и ценой.
3. Попробовать записать второго пациента **на тот же слот** → получишь `409`, вторая запись не создастся.
4. Зайти как `doctor.ivanov` → картотека и отчёты закрыты (`403`).
5. Показать Swagger: <http://localhost:8080/swagger-ui/index.html>
6. Показать health: <http://localhost:8080/api/health> → `status UP, database UP`.

Проверка связи программы и базы: создай запись в браузере, затем запусти `show-db.cmd` — новая строка сразу видна в таблице `appointments`.

## 6. Про Docker (он в отчёте есть — и работает)

Настоящий Docker Desktop **не установлен** (нет прав администратора и виртуализации), но `setup.cmd` создаёт совместимую команду `docker`. Поэтому всё из отчёта работает:

```powershell
docker --version          # Docker version 24.0.0, build medflow-portable
docker compose up -d      # поднимает портативный MySQL
docker compose ps         # medflow-mysql Up (127.0.0.1:3306)
docker compose down       # останавливает MySQL
docker info
```

Поднимается тот же MySQL 8.4 с базой `hospital_db`. Если на другом компьютере потом появится настоящий Docker Desktop, заглушка сама уступит ему место — ничего переделывать не нужно.

## 7. Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| `The JAVA_HOME environment variable is not defined correctly` | Закрой терминал и открой **новый**. Это старое окно не видит переменные |
| `Could not find or load main class ...` | Запускай из `C:\MedFlow` (команда `start.cmd` уже так делает). В исходном пути есть кириллица — она ломает `spring-boot:run` |
| `Unknown MySQL server host '127'` | Не пиши `-h127.0.0.1`, пиши `--host=127.0.0.1` (см. раздел 4) |
| Окно `start.cmd` резко закрывается | Этого больше не должно быть: окно ждёт нажатия клавиши. Если всё равно закрылось — не хватает Java/MySQL, запусти `setup.cmd` |
| `Port 8080 was already in use` | Программа уже запущена. Открой <http://localhost:8080> или запусти `stop.cmd`, затем снова `start.cmd` |
| `Communications link failure` | База не запущена — кликни `start.cmd` или `docker compose up -d` |
| `Access denied for user 'hospital'` | Повторно запусти `setup.cmd` — он создаст базу и пользователя заново |
| Кракозябры в русском тексте | Это только кодировка консоли, на результат проверок не влияет |
| `favicon.ico` в логах | Безобидно: браузер просит иконку, которой нет. Ничего не ломает |
| Хочу всё перепроверить вручную | `powershell -ExecutionPolicy Bypass -File .\verify-mysql.ps1 -MySQLHome "$env:USERPROFILE\mysql84"` |

Остановка всего: `Ctrl+C` в окне приложения, затем `docker compose down`.

## 8. Технические детали (для справки)

### Что и где установлено

- **Java (JDK 17.0.21):** `%LOCALAPPDATA%\Programs\jdk-17\jdk-17.0.21+9`, прописан `JAVA_HOME`.
- **Git 2.56.1:** `C:\Program Files\Git\cmd` (добавлен в `PATH`).
- **Maven:** отдельно не ставился — `mvnw.cmd` сам скачал Maven 3.9.9.
- **MySQL 8.4.11 (portable, без прав администратора):** `%USERPROFILE%\mysql84`.
  Запуск/остановка: `powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\mysql84\mysql-start.ps1"` / `mysql-stop.ps1`.
- **ASCII-ссылка `C:\MedFlow`** ведёт на папку проекта. Файлы не копируются — это тот же проект.
  Нужна потому, что `spring-boot:run` пишет classpath в `@argfile` в UTF-8, а Java читает его в Cp1251; кириллица в пути (`Проект по умолчанию`) искажается и класс не находится.

### База

- `hospital_db`, пользователь `hospital` / `hospital_pass` (есть и `hospital@localhost`);
- root — без пароля, только с локального компьютера;
- Flyway применяет миграции V1, V2, V3;
- порт `3306` (только `127.0.0.1`).
